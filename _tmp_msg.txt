feat(session): 日志格式锚点——会话头 + 方向感知拒绝 + 未知事件守卫

P0-3。日志是唯一事实源，但格式本身没有版本：升级运行时、增删事件类型之后，
旧读取者会静默按自己的理解重建一份**语义不同**的会话。`ignorable` 字段此前
是死字段（定义、序列化、反序列化都在，读取端零检查）。

**会话头**（values/messages.py 的 SessionHeader）——文件级元数据，不是事件：

    {"session": true, "format_version": 1, "id": "main", "time": …}

不复用事件信封：`_log[seq]` 依赖"seq == 下标"（derive_messages 直接按下标取），
让它占 seq 0 会把整库序号平移，并坏掉所有按 seq 取事件的读取方（eval/recall 的
审计脚本就是这么取的）。头只带 version/id/time——**工作区不进头**，它已经有
`session/workspace` 痕迹事件这个家，再放一份就是第二个会漂的副本。

写入：Session.bind_store 顺带 save_header，只在文件为空时写。
读取（values/persistence.py）两道守卫：

- 方向感知拒绝：日志版本 > 读取者 → SessionFormatUnsupportedError（独立异常
  类型，与"损坏"分开：文件什么都没坏），消息含升级方向与文件路径；更旧 →
  返回版本号；没有头的老文件按 v0 读，--resume 照常
- 未知事件默认"必读"：KNOWN_SESSION_EVENT_TYPES 闭集（22 类），不在集合且
  ignorable != True → UnknownSessionEventError；标了 ignorable 的跳过、其余照常重建

只有结构性变化才 bump 版本；词汇增长靠 ignorable，不 bump（"能否自动升级"是
那一步 upgrader 的属性，不该由版本号形态预先承诺）。

读取方同步（头改变了"第一行是事件"的隐含契约）：web/sessions.py 会话列表、
app/recall.py 的 L0 行内快扫、eval/recall/build_dataset.py 与 export_sessions.py
的逐行读——顺带修掉三处"事件数比真实多 1"。

测试 tests/test_session_format.py 七条契约（逐条对应计划 §P0-3 验收表）：
新建会话有头 / 无头老文件按 v0 / 更新的日志被拒 / 未知且不可忽略 → 拒绝 /
未知但 ignorable → 跳过其余重建 / **有头时 derive_messages 与加头之前逐字节一致** /
闭集双向检查（不许漏登记，也不许留僵尸）。
