## 为什么需要"逆向"

代码是在快速迭代里长出来的：每次只解决眼前那一个问题，理由散落在 commit、
`NEXT_STEPS.md` 和十几篇设计记录里。结果是**实现能力**有了，**讲述能力**没有——
面试官问的恰好是后者。

逆向不是重读一遍代码，而是把三种东西重新接起来：

| 已有的 | 缺的 | 补齐动作 |
|---|---|---|
| 代码（怎么做的） | 一条能讲的主线 | 画一条消息的完整生命周期 |
| 设计记录（当时为什么） | 决策的**候选与代价** | 把 note 压成决策卡，并去代码里找落地点 |
| 测试（钉住了什么） | "怎么证明它真的成立" | 每个不变式对应到具体测试文件 |
| `NEXT_STEPS.md`（做完没） | **诚实的能力边界** | 明确列"没做什么、卡在什么前提" |

## 三条会被考的能力

面试官对"自己写的项目"通常只在三个层次上验证，准备也按这三层来：

1. **复述**："讲一下你的项目"——考主线是否清晰，有没有被实现细节淹没。
2. **推导**："加一个工具要改哪几处？""并发后日志顺序为什么还是对的？"——考你是否真的
   掌握了结构，而不是背下了文件清单。
3. **辩护**："为什么不用 LangChain / 为什么不直接把记忆存进数据库？"——考取舍。
   **只讲优点、讲不出代价的项目，会被判定为"抄来的"或"没想过"。**

对应地，验收标准写在[第四节](#四验收三级标准)；自测题在[第六节](#六闭卷自测)。

## 一、逆向的顺序：从动态路径开始，不是从目录树开始

静态读目录得到的是"模块清单"，而面试问的是"一条消息进来发生了什么"。
这个项目的每个状态都围绕同一条事件流，所以**路径即架构**：

```
用户输入 → Inbox（先记账再入队）→ wake 被动状态机 → turn/step 两级循环
        → derive_messages 折叠出记忆 → 模型 → 工具 → 结果落日志 → 再折叠
        → turn/end → 跑空队列 → idle → 重放 = 恢复
```

所以第一遍**只读这一条路径上的代码**（五个文件），把每跳的
"状态住在哪、有没有进日志、失败会怎样"标出来。走完这一遍，80% 的架构已经在手上。

完整路线与每站的验收问题见 [`01-tour.md`](01-tour.md)。

## 二、三遍法

| 遍 | 时长 | 做什么 | 产出（可自检） |
|---|---|---|---|
| **第 0 遍** 跑起来 | 30 min | `--fake` 跑一轮；打开 `.sessions/*.jsonl` 看 20 行；`--resume`；跑 `show_memory.py` | 亲眼见过"记忆是投影" |
| **第 1 遍** 画主线 | 2–3 h | 只沿一条消息的生命周期读代码，画时序图 | 不看代码能画出 12 跳的图 |
| **第 2 遍** 逐层精读 | 1–2 天 | 八站（见下），每站三问 | 能对任意一层做 3 分钟讲述 |
| **第 3 遍** 逆向决策 | 半天 | 只读 `docs/notes/` 的 Problem/Alternatives/Consequences，回代码找落地点与测试 | 每个决定能说出"否决了什么、代价是什么" |

第 0 遍最重要也最容易被跳过：**没有体感的结构是背出来的**，一被追问就会露出。
跑起来之后你会立刻看见两件只在运行态成立的事——`--fake` 的脚本化模型怎么触发工具循环，
以及日志里那些"痕迹事件"（`request/header`、`step/start`）为什么存在。

## 三、八站路线

每站都问同样三个问题：**这层负责什么？它凭什么可以不知道上层？它坏了会怎样？**

| 站 | 读什么 | 带着什么问题 | 读完必须能回答 |
|---|---|---|---|
| 0 跑 | `cli.py`、`--fake`、`.sessions/*.jsonl` | 一条日志行长什么样 | 为什么 `seq` 单调、为什么第一行不是事件 |
| 1 值层 | `values/messages.py`、`persistence.py`、`limits.py` | 词汇表为什么是闭集 | `surface_op` 为什么在写入时校验 |
| 2 状态层 | `state/{session,inbox,registry,prompt}.py` | 谁是事实源，谁是投影 | `_log`/`_surface`/`_state` 三个结构的区别 |
| 3 能力层 | `capability/{llm,hooks}.py` | 内部词汇 ↔ wire 怎么翻译 | 真模型与 `FakeLlm` 为什么不需要共同基类 |
| 4 框架层 | `runtime/{loop,agent}.py` | 两层循环各自回答什么问题 | step 为什么必须等于"一次模型请求" |
| 5 应用层 | `app/{factory,compaction,recall}.py` | 加一个能力要动几处 | "供给面"是什么意思 |
| 6 入口层 | `my_coder/web/`、`cli.py`、仓根 `web/index.html` | 两个宿主为什么不用改框架 | seat 解决了什么，SSE 断开后谁取消谁 |
| 7 门禁 | `tests/test_architecture.py`、`test_docs.py`、`test_doc_numbers.py` | 规则怎么变成不可违反 | 三条门禁各防住哪一种漂移 |

> 第 2 站的 `inbox` 与第 4 站的 `loop` 是本项目信息密度最高的两处，各留足 1.5 小时。
> 第 7 站常被跳过，但它是"工程品味"的唯一硬证据——面试官问"你怎么保证质量"时，
> 说"我写了测试"很弱，说"依赖方向由 AST 解析断言，白名单里的例外必须仍然真实，
> 否则测试主动报红"才是有信息量的回答。

## 四、验收：三级标准

**L1 复述**（能讲清）

- 画出六层依赖图，并说清"四层"是历史叫法（框架四层 = values/capability/state/runtime，
  后来加了 app/tools 与 web/cli 两个外层）；
- 说出五个不变式，每个配一句"违反了会怎样"；
- 说出一次请求里的事件顺序（`step/start → user/message → request/header →
  assistant/message → tool/call → tool/result → step/end`）。

**L2 推导**（能迁移）

- 新需求："加一个 `summarize` 工具"——说出要改的**全部**位置（实现 + schema +
  三处供给面：什么时候用/怎么用/在需求发生处提醒）；
- 新 bug："两个工具并发执行后，日志里的结果顺序和模型请求的顺序不一致"——定位到
  `_run_group` 的 `commit_ready`，并说出不修会坏什么（前缀缓存、重放前缀、前端配对）；
- 新约束："同样的日志必须折叠出同样的记忆"——说出这条约束把哪些实现方式排除了。

**L3 辩护**（能承认代价）

- 对任意一个决定，说出：候选方案 → 为什么否决 → 选中的代价 → 哪个测试钉住它；
- 说出至少 5 个"明确不做"的项及其前提（`NEXT_STEPS.md` 与 `docs/notes/` 里有）。

## 五、日程（两种）

**紧凑版（3 天，每天 4–5 小时）**

| 天 | 上午 | 下午 |
|---|---|---|
| D1 | 第 0 遍跑起来 + 第 1 遍画主线 | 站 1–2，产出自己的时序图 |
| D2 | 站 3–4（loop 慢读） | 站 5，把 `factory.build_agent` 的装配顺序默写一遍 |
| D3 | 站 6–7 | 第 3 遍决策卡 + 闭卷自测 + 对着镜子讲 3 分钟版 |

**稳版（7 天）**：每天一站，D7 只做自测与讲述；多出来的时间用来跑一次真模型端到端
（`--workspace .` 让它改一个真 bug），把"我实际验证过"变成能讲的具体故事。

## 六、闭卷自测

不看任何文件，写出答案；写完再回代码核对。**答不上来的题就是下一站。**
带评分标准的分级练习（12 概念题 + 3 白板推导 + 2 压力题 rubric）在
[`05-drills.md`](05-drills.md)。

1. 日志第一行为什么不是 `SessionEvent`？如果让它占 `seq=0`，会坏掉什么？
2. `derive_messages()` 折叠的是什么？`tool/result` 为什么能以 `surface` 身份进入模型记忆，
   而 `tool/call` 不行？
3. inbox 为什么必须"先落 `agent/inbox/spliced` 再改内存"？反过来会怎样？
4. `peek` 与 `claim` 为什么要分开？取消点落在两者之间会发生什么？
5. step 的粒度为什么必须是"一次模型请求"？旧实现（整段工具循环）的具体故障是什么？
6. `surface_op='replace'` 为什么用**位置**语义而不是 `seq` 数值区间？
7. `execution_mode` 与 `offload` 各回答什么问题？为什么 `offload` 只给纯 I/O？
8. 未注册的工具名为什么在 `mode()` 里返回 `'sequential'` 而不是抛错？
9. 崩溃留下的"悬空工具调用"为什么必须在**恢复时**修，而不能在请求构造时补占位消息？
10. 为什么把 `AGENTS.md` 注入 system 而不是 messages 末尾？运行时状态为什么反过来？
11. Web 端两个会话同时跑为什么要 seat 化？不 seat 化时审批请求会串到哪里？
12. 说出三个"明确不做"的决定，以及各自的**前提条件**（不是理由，是前提）。

## 七、维护约定

- 本目录只写**叙事、路线、决策卡、问答**；机制细节一律链接到 `../architecture.md`。
- **测试数与代码行数不在这里重复声明**：`tests/test_doc_numbers.py` **不扫** `docs/interview/`
  （扫描面是它的 `SCANNED_DOCS`），写在这里就是没人守的第二个副本；要报数就当场跑命令。
  机制常量（8000 字符预算、16 次收尾阈值等）可以引用，因为它们的定义处被测试覆盖。
- 每完成一次真实的面试复盘，把被问倒的问题补进 [`03-qa.md`](03-qa.md) 的追问链；
  **被问倒过的问题才有资格进决策卡**，其余保持精简。
