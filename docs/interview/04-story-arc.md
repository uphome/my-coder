# 演进故事线：这个项目是怎么长出来的

> 本文件是**派生视图**，事实以 [`../architecture.md`](../architecture.md) 与
> [`../notes/`](../notes/) 为准；这里只讲"A 逼出了 B"的顺序与因果。
> "为什么不是另一种"的决策卡在 [`02-decisions.md`](02-decisions.md)，本文不重复。

## 起点（2026-08-19 – 09-10，设计记录制度尚未建立）

- **08-19**：`3d21c51` 对着 deepseek-harness 复刻出可运行骨架——事件日志、被动状态机、
  三个决策钩子、教学注释。
- **08-21 ~ 08-24**：工具面从 1 个扩到 8 个，补上路径沙箱、approval、超时与"失败降级成结果"；
  真模型端到端验收通过（`7769006`，31 passed）。
- **09-05**：压缩引擎落地（`ccfdbc8`、`452d55e`），`replace` 第一次按**位置语义**实现（`74440e5`）。
- **09-10**：插队消息在旧 step 粒度下躺了 **2 分 40 秒**、期间 50+ 次工具调用后被 cancel 清掉；
  step 改成"一次模型请求"（`382d517`）。

> 这一段没有设计记录（记录制度 09-19 才立起来），但它定下了后面所有问题的形状：
> "日志是唯一事实源"开始被当真，于是"日志读不读得回、读不读得到、读不读得起"逐个变成事故。

## 阶段一（09-19）：压缩会丢细节，但数据没丢——缺的是通道

**问题**：压缩 09-05 就上线，却从没量过它丢什么。真实语料（4 个会话、60 MB、20 万+ 事件）里
成功压缩只有 **1 次**；那一次里 12 条被压消息含三段工具输出（约 **4,700** 字符），
而摘要输入只有 **474** 字符——`app/compaction.py` 构造摘要输入时只取 `text` 块，
工具结果对摘要器**确定性地不可见**。评测侧也没有答案：真实语料里"只能靠召回"的样本约 3 条/会话。

**改了什么**：先造仪器再改机制——受控构造会话 + R1/R2/R3 三臂 + 可恢复性审计（`af43cef`）；
再落 L0/L1/L2 三层召回（`82b61e9`），检索面定义为"曾经进过模型上下文的事件全集"（含被遮蔽的）。
中途把"让 LLM 从清单里挑回合"从机制与评测骨架里否掉（13 道导航题：LLM top-1 **38%**，
字面基线 top-1 **69%**）。

**判据**：压缩只改变"看得见什么"、不改变"存在什么"；数据没丢时，该补的是通道，不是摘要质量。

## 阶段二（09-29）："能回到原文"不等于"原文读得到"

**问题**：召回 09-28 合入后立刻用审计回看，16 条稀有"针"里 **6 条读不回来**——5 条被单块
1500 字符上限挡住、1 条被 80 事件上限挡住，而内容都在回合字符预算之内。同一批评测 run
还暴露工具层问题：Windows 上 `bash` 实际落到 `cmd.exe`，15 个 run / 105 条结果里 **22 条**
失败（占全部失败约三分之一）是 `ls`/`cat` 这类不认；同批命令真 bash **12/13** 通过、cmd **5/13**。
规范层同样如此：`AGENTS.md` 长到 **22,553** 字符，而每个文件只注入 **8,000**，
13 个规则块里 **9 个**模型从没看到过。

**改了什么**：召回渲染改成按行分页、截断必须给总量与 `offset` 坐标（`54db8c8`）；
`bash` 显式挑真 bash，回退 cmd 时把方言写进工具描述（`070a055`）；
文档分层，`AGENTS.md` 只留判据 + 链接，长文搬进 `docs/notes/`（`5429705`）。

**判据**：凡是跨边界交付的内容（返回模型 / 交给 shell / 写进规范），降级与截断都必须显式，
不能静默。

## 阶段三（09-30）：模型"再查一下"停不下来——给工具面加收敛压力

**问题**：issue #2 实录：单回合 **15 次模型请求、24 次工具调用**才给结论。真实语料
（4 会话 / 57 个有工具调用的回合 / 435 次调用）里最长连续只读段 p90=**8**、max=**39**；
6 个回合（11%）≥8，涉及 148 次调用（34%）。对照组是一个 **61 步**的实现型长回合，
最长只读段只有 **4**——所以判据不能是总步数，按步数砍会砍掉合法的大任务。
测量本身也翻过车：最初报"29 次重复调用"，用完整参数重量只有 **2 次**
（比较前把参数截断到 70 字符，把"看起来一样"放大了 15 倍）。

**改了什么**：`ToolSpec.cacheable` 声明"这次调用算不算只读、无产出"；`ProgressPolicy` 做
无进展计数（软 8 / 硬 16）；软提示写进**那条工具结果正文**；硬上限用"不带工具面的一步"
收尾，`turn/end` 记 `read-budget`（`e5b5968`）。A/B 实测请求 **−30%**、工具调用 **−35%**，
结论质量没有下降。

**判据**：收敛看"自上次变更以来连续只读调用数"，不看总步数；边改边验的大任务是合法的。

**证据**：[工具收敛](../notes/implemented/feature/2026-09-30-tool-convergence.md) ·

## 阶段四（10-01）：日志被更多人信任——先加锚点、原子点与门禁

**问题**：召回给日志加了更多读取者（eval 脚本、L0 快扫），三个"事实源"层面的缺口同时暴露：

1. **没有版本**：第一行直接是事件，升级/降级后旧进程能"成功"读出一份语义不同的会话；
   `ignorable` 当时是死字段，全仓读取端 **0 处**检查。
2. **取消有窗口**：探针让 `pre_step` 挂 5 秒再取消，消息**三处都不在**——日志只剩
   `spliced removed=1`，队列空、surface 空、没有 `canceled` 记录。
3. **数字与基线全靠自觉**：测试数 175/85/131 vs 实测 **203**（206 含门禁自身），
   "约 1000 行" vs 实测 **7,991**；评测题库 36 + 13 条无保护，第二份重建还要花 API。

**改了什么**：会话头 + 方向感知拒绝 + 未知事件守卫（`2604eee`）；`peek`/`claim` 分离，
两个 await 都提到认领之前，认领到落盘之间无 await（`951592d`）；文档数字现场测量断言
（`759f4cd`）；题库 sha256 锚在 git HEAD 上并写明"不可原地复现"（`016fc3f`）。

**判据**：事实源要有版本锚点与原子提交点；规则要变成测试门禁，不能靠"记得同步"。

## 阶段五（10-03 ~ 10-04）：日志太大——粒度、缓存、内存、界面一起还债

**问题**：一个真实会话 **116.3 MB / 425,854 行**，其中流式帧占 **89.3%** 字节、**98.9%** 行；
一个 step 的 2,793 行 = 736 KB，内容只有 8.9 KB（98–99% 是逐行 JSON 固定开销）。
派生后果一串：`session.events` 单次 **12.1 ms** 且每请求至少读 5 次；4 个会话常驻
**337 MB**；Web 历史只从第 **73/78** 回合开始（132 行），压缩让人"失忆"。

**改了什么**：帧不落盘、每 step 一条汇总（`de236c8`，同一份日志降到约 12.5 MB / 4,530 行）；
`events` 按变更缓存（`9c26a9e`，12.1 ms → 0.0 ms）；席位冷却释放（`9d82154`，常驻上限 3）；
历史改走全量日志（`c52a155`，132 → 1,378 行）；跳帧重放把打开大会话从 **377.7 MB**
降到 **21.8 MB**（`418e4f5`、`ca76143`）。

**判据**：日志只记事实（过程走瞬时通道），内存只留"模型此刻需要 + 定位其余"的索引。

## 阶段六（10-15）：优化埋下的坑——"位置 ≠ seq"一族三个 bug

**问题**：阶段五的跳帧重放让"第 i 条事件的下标就是 i"不再成立：5,617 条事件的 seq
散布在 0…425,984。三处依赖这条隐含前提，且都不主动报错：

1. `append` 用 `len(_log)` 取 seq → 新 seq 从 4,661 重新开始，真实会话出现 **957 个重复 seq**；
2. 两处用 `events[seq]` 索引 tuple → 历史渲染 / 压缩取被压内容要么 `IndexError`、
   要么取到错的事件；
3. 压缩选区端点按数值区间判定，端点是 `(425851, 5501)` 数值倒置 → `_shadowed_messages`
   返回 **0 条**，摘要基于空对话生成，checkpoint 照样遮蔽——**模型永久失去那段历史**。
   第三条不是崩溃，是静默内容损失。

**改了什么**：`_next_seq` 独立游标（`03295c0`）；`by_seq()` 成为唯一的"按 seq 取事件"入口
（稠密走快路、稀疏查 `_sparse`；`8765429`）；选区端点按 surface 位置解释
（`52fb281`，真实会话上 0 条 → **350 条 / 316,897 字符**）。

**判据**：用"身份（seq）"还是"位置（下标）"必须认准一种、不许混用；静默给错数据比崩溃更糟。

**证据**：[位置 vs seq](../notes/implemented/bug-fix/2026-10-15-position-vs-seq.md) ·
`03295c0` `8765429` `52fb281` `55f27bf`

## 一条因果链（面试 30 秒版）

1. **日志只能追加** → 压缩只能改"可见性" → 丢了要补通道（阶段一）。
2. **补了通道** → 才发现"给了入口"不等于"读得到/用得对" → 每段交付都要显式（阶段二）。
3. **模型行为也要机械信号** → 收敛按"无进展只读"，不按步数（阶段三）。
4. **日志被更多读取者信任** → 版本、原子提交、门禁一起上（阶段四）。
5. **信任的代价是体积** → 帧、缓存、席位、历史分别还债（阶段五）。
6. **每次优化都会破坏一条隐含前提** → 跳帧暴露"位置 ≠ seq"（阶段六）。
