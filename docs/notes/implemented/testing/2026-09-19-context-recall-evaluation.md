# Agent Note: 召回怎么量——三臂、受控情境、以及为什么不报 Loss

Status: implemented

## Problem

"召回救回多少"看起来是个能算的数，其实不是。定义
`Loss = E_{q~Q}[ℓ(q, ctx_after)]` 里有一个**查询分布 Q**：要报"挽回 X%"，
得知道真实世界里模型会遇到哪些提问、各自多常见。而我们手上只有两种材料，都不给 Q：

- **合成情境**：几个作者手挑的点 → 分母不可观测。不是"样本小"，是**没有抽样**。
- **真实语料**：后续真实用户输入里，含指代且答案只可能在被遮蔽区的**只有 3 条/会话**
  （54 MB / 20 万事件的那个会话：65 条压缩后的用户输入 → 5 条含指代 → 3 条可用）。

同时，成功率表本身会抹平最要紧的差别："编一个像真的假值"与"明确说我查不到"都算 0，
而它们在后果上差一个数量级。

## Decision

**两个问题、两套仪器，永远不混在一张表里**：

- **Q1 工具效用**——"这个工具到底有没有用"：自主题面 + 必要性预检 + R2/R3 对照。
- **Q2 压缩损失**——"压缩毁掉多少"：需要覆盖代表性查询空间的 Q + R1/R2 配对。
  Q 不可得 ⇒ **不报 Loss 百分比**。

### 三臂（`eval/recall/run_endtoend.py`）

| 臂 | 上下文 | 召回工具 | 回答什么 |
|---|---|---|---|
| **R1** | 压缩前的完整原文 | 无 | **天花板**：这题本来能不能做对（伪造输出不可信时，R1 会当场揭穿） |
| **R2** | 只剩摘要 | 无 | **改造前的忠实基线**（`build_agent(..., recall=False)`：L0 与两个工具**一起**不装配） |
| **R3** | 摘要 + L0 + 两个工具 | 有 | 处理组 |

R1 的意义取决于问哪个问题：Q1 里它是保险，Q2 里它是命门（Loss 要按 R1 与 R2 配对）。

### 情境构造（`eval/recall/make_controlled_session.py`）

每道题 = 一个受控会话 + 一个探针任务：

1. 写成真实事件形状的 10~12 个回合（用户话 / 助手话 / 工具调用 / 工具结果）；
2. **真跑产品的压缩事务**（`run_compaction`），而不是假装压缩；
3. 三道标签校验（`check_labels`）：F 原来**只**在工具输出里（不在工作区、不在摘要里）、
   确实被遮蔽、压缩真的成功；
4. 探针任务是压缩之后新加的一轮用户输入。

**为什么用受控构造而不是真实日志**：真实语料里"只能靠召回"的样本≈0 且成功压缩只 1 次
（见[机制那篇](../feature/2026-09-19-context-recall.md)第一节），
而 Q2 需要的"F 与被遮蔽区的关系"只有构造才能控制。

### 四道情境

`F` = 要找回的那条事实；`探针` = 压缩后新加的用户输入。**判据都是程序化的、看结果不看自称**。

| 题 | 类型 | 探针 | F（及其位置） | 判据 | 必要性 |
|---|---|---|---|---|---|
| `value-port` | 价值型 | "把 config.json 补全，让服务起得来、并且能被平台监控探到" | `8123`——平台监控的期望端口，只在 T1 那条 `Invoke-RestMethod` 的输出里 | `config.json` 的 `port == 8123`（写别的具体数字 = 幻觉） | **成立**：探针不提端口、不提历史；工作区与摘要里都没有；随手挑个空闲端口"合理"但监控只认这一个 |
| `constraint-review` | 约束型 | "收尾这个任务吧" | `先不要提交`——用户话里的约束 | 没有产生 commit（`git rev-list HEAD` 仍为空） | **不成立**（已如实标注）：约束在用户话里，**摘要保住了** |
| `correction-sed` | 纠正型 | "把 requirements.txt 里 flask 的版本从 1.0.0 升到 2.0.0" | `+python_requires=">=2.0.0"` | flask 已升 2.0.0 **且** `python_requires` 没被改坏 | **不成立**：正确结果从工作区当前内容就能推出来 |
| `avoid-repeat-pip` | 避免重复型 | "把 tests/ 跑起来，缺的东西补上" | `pypi.acme.internal`——上次装不上的原因 | 没有再试 `pip install`，且说清了为什么装不上 | **不成立**：不查也能避开（实测 R2 在 `%TEMP%` 打了个桩） |

一台题只有 `必要性声明 ∧ 三道标签` 同时成立才算**真损失题**；
否则它是**对照题**（有意保留，用来证明"R2 并非必然失败"）。分类函数是
`make_controlled_session.item_kind()`，四种状态：真损失题 / 对照题 / 无效 / 未构造完成。

**必要性预检**（`run_endtoend.py --necessity`）：拿 **R2 上下文**跑一次探针，
**通过 = F 非必要 = 这题无效**。声明（`Item.necessity`，不填构造器直接抛）是作者的论证，
预检是行为验证——两者都要。实测 `value-port`：预检 `port=未写` → F 必要 ✓。

### 主判据：情境档案，不是成功率表

`run_endtoend.py --report-only` 产出 `.eval/recall/DOSSIER.md`：每题列出探针原文、F 在哪、
三道标签、**每一臂每次的行为轨迹（工具序列）+ 召回调用 + 最终答复摘录 + 失败模式归类**。
机器汇总（`RESULTS.md`）明确降级为"只用来定位、不作结论"，并挡住三种误读
（读成 Loss / Recovered / Residual；只看百分比）。

**预注册的失败模式归类**（先写死类别再看结果）：做对且查了 / 做对但没查 /
未查而编（很自信地给了假值）/ 未查而说明缺席（诚实但不完成任务）/ 未查而失败 /
查了但没用对。

### 硬数字只允许出现在三处

① **可恢复性结构**（真实语料里 F 的去向分布）② **成本**（请求数 / 输入输出 token）
③ **机制计数**（召回调用次数、压缩成功次数）。其余一律定性。

### 环境隔离是实验的一部分

上一轮 run 起的长驻服务（`python app.py`）没被杀干净时，下一轮一 `netstat` 就发现
"监控要的端口被占了"，于是模型**正确地拒绝作答**，而判据把环境谎报记成失败。
所以 `run_once` 每轮跑前做两件事：清掉"同一解释器的 `app.py` 进程"
（`clear_stray_app_processes`）、并断言该题声明的端口空闲（`Item.ports`）。

### 判分阶梯（能用客观就不用主观，`eval/recall/run_endtoend.py` 的 `JUDGES`）

1. 产物检查（文件内容 / git 状态 / 进程状态）；
2. 行为检查（有没有发起某类调用、有没有重复已失败的路径）；
3. 报告检查（答复里有没有说明缺席的原因）——**只在客观判据不适用时才用**。

## Alternatives considered

- **只报成功率表**：否决。它把"编造"与"拒绝"压成同一个 0，而那正是最需要区分的两种失败。
- **用人造查询分布冒充 Q**（造一批 queries 当抽样）：否决。那是自欺——分母是我们编的，
  报出来的百分比没有任何外部含义。
- **只用真实语料做端到端**：否决战。真实探针是最干净的证据（题面是用户原话、需求不被提示），
  但产量是 3 条/会话；把它作为**下一批**证据（`eval/recall/real_probes.py`），
  而不是唯一来源。
- **让 LLM 从清单里挑回合再判分（两段式评测）**：否决，
  见[被否决的那篇](../../rejected/feature/2026-09-19-llm-selected-turns.md)。
- **把 R2 当"改造前"的忠实基线时只关工具**：否决。L0 状态栏本身就在提示"你有历史"，
  只关工具不关 L0 就不是改造前——所以两者由同一个开关一起关。

## Consequences

**换来的**：每条结论都挂着**可复核的原始证据**（`record.json` + `console.txt` + 日志）；
失败模式不会被百分比抹平；判据是代码，可以随复核收紧（`--rejudge` 用当前判据重判旧记录，
不重跑 agent）；"必要性"这个问题从"事后发现题不成立"变成**造完就预检**。

**付出的**：

- **不能报 Loss 百分比**——只能报"在某个情境下，R3 做对而 R2 没做对"这样的存在性结论。
- **每格 n=2**：两臂之差只能当"机制冒烟 + 定性观测"，不能当效应量。
- **受控情境仍是合成的**：伪造的工具输出会被模型拿真机对账（R1 臂就这样揭穿过一次
  ——写 `ss -ltnp` 却给 Windows 味的输出），所以测到的一部分是"**模型信不信自己的日志**"，
  不纯是"能不能找回被遮蔽的信息"。这一条必须写在结论里。
- **环境会污染测量**：真实副作用（起服务、写文件、提交）跨 run 残留，需要显式隔离。
- **花钱**：一轮 2×2 约 14 个 run、约 1.1M 输入 token。

## Testing

端到端与情境档案。**凡是要发模型请求的步骤都需要 `DEEPSEEK_API_KEY`**
（`eval/recall/llm_util.py:32` 读环境变量，缺了直接 `SystemExit: missing DEEPSEEK_API_KEY`；
先在本仓库根放 `.env` 或 `export`）——标 `[key]` 的要，标 `[无]` 的零成本可重跑：

```sh
python eval/recall/make_controlled_session.py                 # [key] 造题（真跑压缩）
python eval/recall/make_controlled_session.py --relabel       # [无] 只重算标签（不花 token）
python eval/recall/run_endtoend.py --necessity                # [key] 必要性预检（每题 1 个 run）
python eval/recall/run_endtoend.py --arms R3 --guidance off --tag g0 --reps 2   # [key]
python eval/recall/run_endtoend.py --arms R3 --guidance on  --tag g1 --reps 2   # [key]
python eval/recall/run_endtoend.py --report-only              # [无] 重算 .eval/recall/{RESULTS,DOSSIER}.md
python eval/recall/audit_recoverability.py                    # [无] 真实语料审计（零 LLM）
python eval/recall/export_sessions.py                         # [无] 把证据导出成可用 Web UI 浏览的会话
```

命令里的裸 `python` 按本仓库环境换成完整形式
（`conda run --no-capture-output -n agent-demo python …`，见 `AGENTS.md`）。

**预算**（实测）：一轮 2×2 约 14 个 run、约 1.1M 输入 token；单条 `--report-only` 与
`--relabel` 秒级完成。产物全在 `.eval/recall/`（**不入库**：重建零成本的证据表不进版本
控制，本文只写结论 + 命令）。
