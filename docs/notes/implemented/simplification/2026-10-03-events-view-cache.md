# Agent Note: 事件视图按变更缓存（消掉每请求的整表拷贝）

Status: implemented

## Problem

`Session.events` 每次都 `tuple(self._log)`——**整表拷贝**。实测（冻结快照，425,985 事件）：

| 指标 | 修前 |
|---|---:|
| `session.events` 单次访问 | **12.1 ms** |
| `events_since(尾部 10 条)`（既有增量 API） | 0.031 ms |
| `derive_messages()` 单次 | 0.1 ms（132 条） |

而**每个请求**至少读它 5 次：`inbox`（判待处理）、`app/tools/todo.py`（状态栏投影）、
`app/recall.py`（L0 会话目录）、`runtime/loop.py`、`web/payload.py`。于是每次请求几十毫秒，
而且**反复重建 40 万元组**——这既是延迟，也是"重放/峰值内存 590 MB"的主因之一。

注意：**`derive_messages` 不是瓶颈**（0.1 ms）。原先"A/B 里每请求重建全部消息"的怀疑
在这里被测量否掉了——所以本项**没有**去动它。

## Decision

`events` **按变更缓存**：`_events_cache: tuple | None`，脏了下次访问重建一次。

- **失效点只有两个**：`append` 与 `adopt`——它们也是 `_log` 仅有的写入者（已核对全部
  `_log` 引用）。两处都在写入后立刻置 `None`。
- **不改 `events` 的契约**：仍然返回不可变元组、仍然"同一份日志 → 同一批事件"；
  只是同一份日志现在返回**同一个元组对象**。想拿增量的调用方继续用
  `event_count` / `events_since`（既有 API，未动）。

效果（同一份快照）：`session.events` 单次 **12.1 ms → 0.0 ms**（热读 O(1)）。

## Alternatives considered

- **`events` 直接返回 `self._log`**——**否决**：那会把可变列表交出去，任何调用方一改就绕过
  校验与投影（`append` 是唯一的写入闸口，这条闸口不能开）。缓存元组同样是 O(1)，
  却保住了不可变契约。
- **要求所有调用方改用 `events_since`**——**部分否决**：`events_since` 早已存在，也确实更省，
  但"每个调用方都记得自己维护游标"是**把正确性寄托在纪律上**；全表读的场景（历史、压缩、审计）
  本来就需要整表。缓存让"想读全表的人"不再为读一次付 12 ms，且对既有代码零改动。
- **`derive_messages` 也做增量**——**否决（本项不做）**：实测 0.1 ms，收益远小于它引入的
  失效复杂度（要区分"surface 只追加"与"replace 改序"）。将来若它真的变贵，再单独一篇。

## Consequences

**换来的**：每请求那 5 次全表读从"5 × 12 ms + 5 份 40 万元组"变成"一次重建 + 若干 O(1)"。

**付出的与风险**：

- **返回的元组是共享对象**：`session.events is session.events` 现在为真。元组不可变，
  所以安全；但它意味着**长期持有该引用会保住整份日志**（这在缓存之前也是事实——
  每次拷贝出来的元组同样保住整份日志，只是没人会持有）。
- **缓存失效必须挂在所有写入点上**：漏一个就会**静默读到旧日志**（最难查的一类 bug）。
  现在只有两处，测试用"变更后必须是新对象 / 重放后长度正确 / 缓存后投影与从零重放逐字节一致"
  钉住；将来若出现第三个 `_log` 写入者，必须同时挂上失效。
- **`surface` 没有同样处理**：它每次也 `tuple(self._surface)`，但只有 138 项（实测成本可忽略）。

## Testing

证据类型：**单元测试（零 API，3 条）+ 真实快照的测量**

- `tests/test_session_events_cache.py`：
  1. 无变更时 `session.events is` 上一次的元组；`append`/`adopt` 之后必须是**新**元组且长度正确；
  2. 缓存不改变语义：带 `replace`（压缩）的会话，**缓存热了之后再 append**，
     `derive_messages()` 与"从零重放同一批事件"的结果**逐字节一致**；
  3. 效果护栏：42 万事件下，200 次热读总耗时 < 单次冷读（用比值，避免机器差异导致 flaky）。
- 测量脚本（`.eval` 里的临时探针）：同一份冻结快照，`events` 12.1 ms → 0.0 ms。
