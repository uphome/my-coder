# Agent Note: 渲染器的静默截断——把"能回到原文"与"原文读得到"之间的差补上

Status: implemented

## Problem

召回链路可以完全正确，而模型仍然读不到它要找的东西：**渲染器自己会静默丢内容，
而且没有任何参数能把它读回来**。

`app/recall.py` 原有两处上限，都只补一个 `…`：

- `render_message` 对文本块与工具结果**单块截 1500 字符**、工具调用参数截 300 字符；
- `render_turn` 还有 `max_events=80` 与 `max_chars=12000` 双上限。

`step` 过滤与（当时不存在的）分页都作用在**回合层**，块内的后半截根本不进输出——
所以"这块被砍了"这件事，模型既不知道砍了多少，也没有办法继续读。

实测（真实语料审计 `python eval/recall/audit_recoverability.py`，零 LLM）：
一次成功压缩里抽到 16 条"针"（稀有度 df≤2），其中 **6 条读不回来**——
**5 条被单块 1500 字符上限挡住、1 条被 80 事件上限挡住**；而这 6 条的内容
**都在回合字符预算之内**。也就是说：日志里有、检索面覆盖、`read_turn` 也"成功返回"了，
但返回的文本里没有它。

## Decision

**截断只允许发生在一个地方，且必须自报家门。**

- `render_message(limit=None)` **默认不截断**；`render_turn` 不再按事件数截断。
- `render_turn` 改成**按行分页**：`offset` 是 **1 起的行号**（与 `read_file` 同一套心智），
  `max_chars`（默认 12,000）是本次字符预算，**在行边界停**。
- 显示不全时一律追加：
  `…（本回合共 X 行 / Y 字符，本次显示第 A–B 行；继续用 offset=B+1，或用 step 精读其中一步：…）`
  ——总量、位置、下一步坐标、可用 `step` 全给。
- `offset` 越界不假装成功：直接回"offset=N 超出范围：本回合共 X 行 / Y 字符；offset 从 1 起"。
- `read_turn` 的 `description` 同步改成"长回合按行分页返回，输出会说清总行数、给了哪几行、
  用哪个 offset 继续"。
- 工具层对 `offset` 做**严格类型校验**（`offset=0` / 非整数 → `is_error`）。
- L1 同步补三条规则（截断明说 + 给 `read_turn` 坐标；重复用户话标注；无结论显式说明），
  动机与实测见[机制那篇](../feature/2026-09-19-context-recall.md)。
- 审计脚本的分类跟着改：不再有"被单块/回合上限挡住"，改成
  "第一页就有 / 要翻页 / 真损失（渲染器不产出）"。

**同一份审计改前 vs 改后**：读不回来的 **6 → 0**；其中 5 条从"读不到"变成"要翻页"。

## Alternatives considered

- **只把块级上限调大（1500 → 4000）**：否决。那只是把静默截断推到更远的地方，
  长工具输出（实测单块可上万字符）仍然读不全，而且"被砍了"依旧不说。
- **给每块加一个 `block` 参数**：否决。块编号是渲染器的内部结构，模型看不到也不该依赖；
  行分页对模型更自然（`read_file` 就是这么分页的），且对"一个巨大块"同样有效。
- **保留 `max_events`，只放开字符限制**：否决。事件数与内容量不是一回事：
  80 条一行事件（每条几字符）远小于预算，却会被这个上限砍掉——审计里正是 1 条这样丢的。
- **在截断处只写"…（已截断）"**：否决。模型据此无法继续读（不知道总量、不知道步长），
  等于把静默失败换成显式死路。

## Consequences

**换来的**：**"能回到原文"终于等于"原文读得到"**；分页坐标与 `read_file` 一致，
模型不需要学第二套心智；溢出时它知道总量与下一步；审计有了一个可复现的判据。

**付出的**：

- 一次 `read_turn` 可能返回**更多字符**（默认 12,000，此前块级上限在大块上会把它压到 1,500）
  ——成本上限仍然存在，但需要模型自己分页，多一轮请求。
- 行分页按**行**切，超长单行（一行几千字符的工具输出）会整行进结果，理论上突破字符预算
  ——真实数据的工具输出里没有这种行；这是一条**已知的边界**，不是隐藏行为。
- `eval/recall/` 里用旧渲染构建的题库（`navigation.jsonl` / `questions.jsonl`）
  与新渲染**不再逐字节一致**：要复现旧数字必须回到旧提交，或按新渲染重建
  （`eval/recall/manifest.py` 的模块注释记了这件事）。
