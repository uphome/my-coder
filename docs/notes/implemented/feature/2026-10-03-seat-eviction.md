# Agent Note: 冷却席位释放（常驻会话收敛到 3 个）

Status: implemented

## Problem

`Seat` 里是**整份 `Session`**（= 整份日志在内存里），而 Web 宿主会**一直保留**打开过的会话
（`web/state.py` 的 `state.seats`）。于是内存按**打开的会话数**线性叠加。实测（2026-10-03）：

| 场景 | 私有内存 |
|---|---:|
| 4 个较小会话（最大 63.8 MB 日志） | **337 MB** |
| 一个大会话（117 MB 日志 / 425,985 事件） | **484 MB**（工作集 497 MB） |

这是 #46 三条里的第一条，也是唯一**不碰 state 层**的一条。

## Decision

`web/sessions.py` 新增 `evict_idle_seats(keep, max_open=MAX_OPEN_SEATS=3)`，在
**`open_session_seat` 新建席位之后**调用一次——不搞后台任务："打开新会话"正是常驻席位
增长的那一刻，在这里收口最简单也最好测。

判据（顺序即优先级，每条都对应一个事故形状）：

1. **只释放空闲席位**（`Seat.is_idle()`：不在跑 **且** 无活跃 SSE 流 **且** 无待审批）——
   释放 = 丢掉整个 Seat 的内存状态；正在跑的回合绝不能拔，否则日志里只剩半个回合；
2. **永远保留** `keep`（刚打开的）与 `state.current_sid`（前端正在看的）；
3. 仍超编就按 `last_used` **最久没用过的先释放**（LRU 式；更新点只在 `open_session_seat`，
   切会话与发消息都要经过它，所以粗粒度足够）；
4. **全忙时允许超编**（fail-closed）：宁可超出上限，也不动进行中的回合。

**释放不等于丢数据**：日志是唯一事实源、磁盘 ≥ 内存（不变式③），重开时
`open_session_seat` 重新 `adopt` 重放即可——丢的只是内存里那份缓存。

## Alternatives considered

- **后台定时任务扫描并释放**——**否决**：多一个与请求生命周期无关的调度器要测；
  席位增长本来就发生在"打开新会话"这一刻，就地收口即可。
- **按时间 TTL 释放（比如闲置 10 分钟）**——**否决（本期不做）**：TTL 需要时钟注入才好测，
  而"上限 + LRU"已经能保证**常驻集合有界**这个要害；TTL 只是让空闲期更省，收益小。
- **释放时把 Session 序列化成快照再丢掉**——**否决**：日志本身就是快照，
  再存一份等于造第二事实源。
- **干脆不保留任何席位（每次都重放）**——**否决**：那会把"打开会话"的成本从内存搬到每次切换，
  而且是**全量重放**（117 MB / 5.2 s）。

## Consequences

**换来的**：常驻席位有界（默认 3），内存不再随"打开过多少会话"无限增长；
多会话并行时进程不炸。**释放路径复用既有的重放机制**，没有新增恢复逻辑。

**付出的与风险**：

- **重开有成本**：被释放的会话再次打开要重放日志（本例 5.2 s / 117 MB）——这是**有意的取舍**：
  用"偶尔重放一次"换"常驻内存有界"。[冷热分层那篇](../../proposed/architecture/2026-10-03-session-log-tiering.md)
  会把这次重放的代价一起降下来。
- **`last_used` 是粗粒度**（只在 `open_session_seat` 更新）：长时间挂在同一个会话上不停发消息，
  它的时间戳会被刷新（因为每条消息都经过 `open_session_seat`），但"只是滚动页面"不算使用。
  这在"挑一个空闲席位释放"的语义下足够。
- **上限是常数**：3 是拍的值，不是测出来的。改它只需改 `MAX_OPEN_SEATS`；
  真正的判据是"全忙时允许超编"，所以调大调小都不会出错，只影响常驻内存。

## Testing

证据类型：**单元测试（零 API，4 条）**

`tests/test_seats.py`：

1. `Seat.is_idle()` 三个条件各自为假时都不算空闲（在跑 / 有 SSE 流 / 有待审批）；
2. 超过上限时**最久没用过的空闲席位**被释放、刚打开的留着；
3. **重开被释放的会话**不报错，`Session` / `Agent` 都由重放恢复；
4. **全忙时一个都不释放**（允许超编）——`init_web` 自带的默认席位（`current_sid`）同样受保护，
   所以断言写成"忙的一个都没少"而不是写死总数。
